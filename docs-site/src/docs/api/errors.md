# API 常见错误

本页汇总 API 调用时最常见的错误含义和排查方向。

## 状态码速查

| 状态码 | 常见原因 | 处理建议 |
|--------|----------|----------|
| 400 | 请求体格式错误、缺少必填字段 | 检查 JSON、模型名和接口路径 |
| 401 | API Key 错误、禁用、过期或认证头错误 | 重新复制令牌，确认认证方式 |
| 403 | 分组不匹配、模型无权限、策略限制 | 换正确分组令牌，查看模型广场 |
| 404 | Base URL 或路径错误、模型不存在 | 确认 `/v1` 是否需要填写 |
| 408 | 请求超时 | 减少上下文、检查网络和代理 |
| 429 | 并发、RPM、周期额度或上游限流 | 降低并发，等待限制恢复 |
| 500 | 服务内部错误 | 稍后重试并保留请求时间 |
| 502 / 503 | 上游或渠道不可用 | 查看可用渠道，稍后重试 |
| 504 | 上游响应超时 | 图片或长上下文请求可适当延长客户端超时 |

## 报错时先看三件事

1. **Base URL 是否正确**：OpenAI 兼容通常要 `/v1`，Claude/Gemini 通常不需要。
2. **令牌分组是否正确**：不要用 CC 分组调用 Codex，也不要用 Codex 分组调用 Gemini。
3. **模型名是否存在**：以模型广场和可用渠道显示为准。

## 联系支持时不要泄露完整 Key

请提供：

- 请求时间；
- 客户端名称；
- Base URL；
- 模型名；
- 状态码和错误信息；
- API Key 前后几位即可。

不要发送完整 API Key、完整 Cookie、OAuth token 或服务器私钥。
