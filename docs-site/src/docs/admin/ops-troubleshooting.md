# 管理员排障

本页提供管理员侧排查思路，用于定位用户调用失败、渠道不可用、计费异常和支付问题。

## 用户调用失败

优先收集：

- 用户 ID 或邮箱；
- API Key 前后几位；
- 请求时间；
- 模型名；
- 客户端和 Base URL；
- 状态码和错误信息。

排查顺序：

1. 用户余额、订阅和分组权限；
2. API Key 是否启用、是否有 IP 或模型限制；
3. 分组是否存在可用账号；
4. 账号是否可调度、是否有错误或限流；
5. Ops 请求错误和上游错误详情；
6. 最近是否修改过模型映射或价格。

## 计费异常

检查：

- 用量记录是否重复；
- 客户端是否自动重试；
- 模型倍率和分组倍率是否符合预期；
- 图片、长上下文或工具调用是否导致高消耗；
- 用户是否共享 Key 给多人或自动化任务。

处理前建议先冻结或禁用可疑 Key，防止继续扩大损失。

## 支付异常

检查：

- 支付实例是否启用；
- 订单金额、币种和支付渠道是否一致；
- 支付平台是否回调；
- webhook 签名是否通过；
- 订单状态是否被重复处理；
- 用户余额或订阅是否成功写入。

## 上游账号异常

检查：

- OAuth token 是否过期；
- API Key 是否失效；
- 账号是否触发上游风控或额度限制；
- 代理是否不可用；
- 模型列表是否变化；
- 是否需要刷新账号或临时下线。
