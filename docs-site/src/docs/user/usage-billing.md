# 用量与计费排查

FreeCode 会根据模型、分组倍率、请求量和站点计费策略记录用量。用户可以通过仪表盘和用量记录了解余额消耗情况。

## 为什么会扣费

一次 API 调用通常会根据以下因素产生费用：

- 使用的模型；
- 输入与输出 token 数；
- 图片生成、图片编辑等非文本能力；
- 当前令牌所在分组的倍率；
- 站点设置的折扣或加价策略。

实际价格和可用模型以控制台的模型广场、分组说明和站点公告为准。

## 分组倍率怎么看

在 [模型广场](../token/1-intro.md) 中，分组名旁边可能会显示类似 `x0.5`、`x1`、`x1.5` 的倍率：

- `x0.5`：按基础价格 50% 计费；
- `x1`：按基础价格计费；
- `x1.5`：按基础价格 150% 计费。

同一个模型在不同分组中可能有不同倍率。创建令牌前请先确认分组是否符合你的用途和预算。

## 余额、订阅和令牌额度

调用是否成功，通常同时受这些条件影响：

| 条件 | 影响 |
|------|------|
| 账户余额 | 余额不足会导致无法继续调用 |
| 订阅权益 | 某些分组或模型可能需要订阅 |
| 令牌额度 | 单个 API Key 达到额度后会被限制 |
| 周期限制 | 5h / 1d / 7d 等周期额度耗尽后需要等待恢复 |
| 并发限制 | 同时请求过多可能触发限流 |
| 上游状态 | 上游账号或渠道不可用时可能失败 |

## 常见扣费疑问

### 令牌设置了无限额度，为什么仍然不可用？

无限额度只表示该令牌本身不设置局部额度上限。它仍然受账户余额、订阅状态、分组权限、速率限制、并发限制和上游可用性影响。

### 为什么同一个模型消耗不一样？

可能原因包括：

- 输入上下文长度不同；
- 输出内容长短不同；
- 是否启用了工具调用、图片输入或图片输出；
- 选择了不同分组倍率；
- 客户端自动重试导致多次请求。

### 为什么失败请求也有记录？

用量记录中可能会保留失败请求，便于排查错误。是否计费取决于请求是否已经到达上游并产生实际消耗，以及站点的计费策略。

## 排查建议

1. 在用量记录里按时间查找失败请求。
2. 记录请求使用的 API Key、模型、客户端和报错信息。
3. 检查令牌分组是否匹配模型。
4. 检查可用渠道中对应平台是否可用。
5. 如果余额异常消耗，先禁用可疑令牌，再联系站点支持并提供时间范围。
