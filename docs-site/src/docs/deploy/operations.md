# 运维检查清单

部署完成后，建议建立固定的运维检查流程，避免账号池、支付、计费和日志长期无人关注。

## 每日检查

- 服务进程是否运行；
- 数据库和 Redis 是否正常；
- 后台 Ops 是否存在大量 5xx 或上游错误；
- 账号池是否有大量不可调度账号；
- 渠道监控是否出现连续异常；
- 支付订单是否有长时间待支付或已支付未到账；
- 磁盘空间和日志增长是否异常。

## 每周检查

- 备份是否成功生成并可恢复；
- 过期账号、异常账号和无效代理是否清理；
- 分组倍率和模型映射是否仍符合运营策略；
- 公告、条款和价格说明是否需要更新；
- 管理员账号和 OAuth 配置是否符合安全要求。

## 发生故障时

1. 先判断影响范围：所有平台不可用，还是某个分组/模型不可用；
2. 查看 Ops 错误、请求详情和上游错误；
3. 检查最近是否修改了账号、分组、模型映射或价格；
4. 对单个账号执行测试或刷新；
5. 必要时临时下线异常账号或切换渠道；
6. 故障恢复后复盘原因，更新文档或监控规则。

## 安全提醒

- 管理后台不要暴露弱口令；
- 支付、OAuth、上游账号凭据必须脱敏保存和传输；
- 定期检查管理员操作和异常登录；
- 对外公告中不要包含服务器路径、私钥、真实 token 或完整用户数据。
